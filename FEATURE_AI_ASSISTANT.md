# AI функции: Two-Stage Processing и AI Assistant 🤖

## Обзор AI возможностей

USM-Service использует AI на двух уровнях:

### 1. 🚀 Two-Stage AI Processing (v2.2.0)
Двухэтапная обработка **при генерации карты**:
- **Stage 1 (Enhancement)**: AI улучшает требования перед генерацией
- **Stage 2 (Generation)**: Генерация качественной карты из улучшенных требований

### 2. ✨ AI Assistant (v2.1.0)
Точечное улучшение **отдельных карточек** после генерации.

# Two-Stage AI Processing 🚀

## Концепция

```
Пользователь: "приложение для доставки еды курьер и клиент"
                    ↓
        ┌───────────────────────────────┐
        │  STAGE 1: Enhancement         │
        │  AI улучшает требования       │
        │  (3-5 секунд)                 │
        └───────────────────────────────┘
                    ↓
        ┌───────────────────────────────┐
        │  EnhancementPreview Modal     │
        │                               │
        │  Ваш текст │ Улучшенный текст │
        │                               │
        │  ✓ Добавлено:                 │
        │    - Роли: Клиент, Курьер     │
        │    - Платформы: iOS, Android  │
        │    - Функция оплаты           │
        │                               │
        │  💡 Рекомендуется уточнить:   │
        │    - Способы аутентификации   │
        │                               │
        │  [Мой текст] [✏️] [✨ Улучш.] │
        └───────────────────────────────┘
                    ↓
        ┌───────────────────────────────┐
        │  STAGE 2: Generation          │
        │  Генерация карты              │
        │  (25-35 секунд)               │
        └───────────────────────────────┘
                    ↓
              Качественная карта!
```

## Преимущества

| Метрика | Без Enhancement | С Enhancement | Изменение |
|---------|-----------------|---------------|-----------|
| Качество карт | Среднее | Высокое | +20-30% |
| Время | 25-35 сек | 28-40 сек | +3-5 сек |
| Стоимость | ~$0.035 | ~$0.036 | +3% |

**Rate Limit:** 30 запросов в час

### POST `/generate-map` (обновлён)

Теперь поддерживает двухэтапную обработку.

**Request:**
```json
{
  "text": "приложение для доставки еды курьер и клиент",
  "skip_enhancement": false,
  "use_enhanced_text": true
}
```

**Параметры:**
- `skip_enhancement` (bool, default: false) — пропустить Stage 1
- `use_enhanced_text` (bool, default: true) — использовать улучшенный текст

# AI Assistant для точечного улучшения карточек ✨

## Описание

Интерактивная фича для улучшения пользовательских историй через AI запросы. Позволяет быстро улучшать качество карточек, добавлять детали, улучшать критерии приёмки, разделять истории и добавлять edge cases.

## Функциональность

### 🎯 Основные возможности

1. **Кнопка "✨ AI Assistant" на каждой карточке**
   - Расположена рядом с кнопкой "Редактировать"
   - Открывает модальное окно с AI помощником

2. **Быстрые действия (Quick Actions)**
   - 📝 **Добавить детали** - расширяет описание истории
   - ✅ **Улучшить критерии** - улучшает acceptance criteria
   - ✂️ **Разделить** - разделяет историю на несколько независимых
   - ⚠️ **Edge cases** - добавляет граничные случаи и обработку ошибок

3. **Свободный текстовый запрос**
   - Возможность ввести свой собственный запрос к AI
   - Примеры: "Добавь больше деталей про оплату", "Добавь edge cases для offline режима"

4. **История улучшений**
   - Отслеживание всех выполненных улучшений
   - Показывает временные метки и результаты

5. **Опция разделения историй**
   - AI может предложить разделить сложную историю на несколько более мелких
   - Показывает предварительный просмотр новых историй
   - Одним кликом создаёт новые истории и удаляет оригинальную

## Безопасность и производительность

### Rate Limiting
- **Single improve:** 20 запросов в час на пользователя
- **Bulk improve:** 10 запросов в час на пользователя
- Реализовано через `slowapi`

### Redis кеширование
- Результаты AI запросов кешируются на 1 час
- Ключ кеша: `improve:{story_title}:{prompt}:{action}`
- Автоматическая обработка недоступности Redis

### Валидация
- Минимальная длина промпта: 3 символа
- Максимальная длина промпта: 1000 символов
- Проверка владельца проекта перед улучшением
- Timeout для AI запросов: 30 секунд

## AI Промпты

### System Prompt
```
Ты — эксперт Product Manager и Business Analyst. 
Твоя задача — улучшать пользовательские истории (User Stories) на основе запросов пользователя.

ВАЖНО: 
- Все тексты должны быть на РУССКОМ языке
- Сохраняй структуру и формат истории
- Будь конкретным и практичным
- Возвращай ТОЛЬКО валидный JSON без дополнительного текста
```

### Quick Actions промпты

1. **details:** "Добавь больше деталей и конкретики в описание истории. Расширь контекст использования."

2. **criteria:** "Улучши и расширь acceptance criteria. Сделай их более конкретными, измеримыми и полными."

3. **split:** "Проанализируй историю и предложи, как её можно разделить на 2-3 более мелкие, независимые истории."

4. **edge_cases:** "Добавь edge cases (граничные случаи) в acceptance criteria. Подумай об ошибках, крайних ситуациях, offline режиме."

## Примеры использования

### Пример 1: Добавление деталей

**До:**
```
Title: Оплата заказа
Description: Пользователь может оплатить заказ
AC: [Оплата проходит]
```

**Запрос:** "Добавь больше деталей про оплату"

**После:**
```
Title: Оплата заказа через платёжную систему
Description: Как клиент, я хочу оплатить заказ банковской картой через безопасный платёжный шлюз, 
чтобы быстро завершить покупку и получить подтверждение оплаты
AC: 
  - Пользователь видит доступные способы оплаты (карта, Apple Pay, Google Pay)
  - Форма оплаты защищена SSL сертификатом
  - После успешной оплаты показывается номер транзакции
  - Пользователь получает email с подтверждением
  - При ошибке оплаты показывается понятное сообщение
```

### Пример 2: Улучшение критериев

**До:**
```
AC: [Пользователь может войти, Показывается ошибка если неправильный пароль]
```

**Запрос:** "Улучши acceptance criteria"

**После:**
```
AC:
  - Пользователь может войти с валидным email и паролем
  - Форма валидирует формат email перед отправкой
  - После 3 неудачных попыток показывается капча
  - При неправильном пароле показывается: "Неверный email или пароль"
  - Кнопка "Войти" неактивна пока поля не заполнены
  - Пользователь может переключать видимость пароля (👁️ иконка)
  - После успешного входа редирект на страницу, с которой пришёл
```

### Пример 3: Разделение истории

**До:**
```
Title: Управление профилем пользователя
Description: Пользователь может просматривать и редактировать свой профиль, менять пароль, 
загружать аватар, управлять настройками уведомлений
```

**Запрос:** "Раздели эту историю на отдельные"

**После:** 3 новые истории:
1. Редактирование базовой информации профиля (имя, email, телефон)
2. Смена пароля и настройки безопасности
3. Управление аватаром и настройками уведомлений

### Пример 4: Edge cases

**Запрос:** "Добавь edge cases для offline режима"

**Результат добавляет:**
```
AC (дополнительно):
  - При потере интернета показывается баннер "Нет подключения"
  - Форма блокируется до восстановления соединения
  - Если пользователь был offline, при подключении проверяется актуальность сессии
  - Кнопки показывают loading state при медленном интернете (>3 сек)
```

## Известные ограничения

1. **Rate Limits жёсткие**
   - 20 запросов в час может быть мало для активных пользователей
   - Можно увеличить в `@limiter.limit()` декораторе

2. **Split action в bulk**
   - Не поддерживается для массового улучшения
   - Нужно использовать single improve

3. **История улучшений**
   - Хранится только в памяти компонента (не персистится)
   - При закрытии модального окна история теряется

4. **Offline режим**
   - AI Assistant требует интернет соединение
   - При offline будет ошибка подключения
